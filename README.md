# CleanMac

原生 macOS 磁盘空间分析应用，使用 Swift 和 SwiftUI。

扫描、归属分析与报告生成均在本机进行，不自动上传磁盘清单或调用外部 AI。将概述交给外部 Agent 前，请自行检查其中的路径、应用和服务信息。

## 当前限制

- “全面分析”覆盖应用配置的六个根目录，不代表覆盖所有挂载卷；无法读取的内容会提示，符号链接可能不收录。
- 大规模扫描仍可能占用较多内存，结果发布时也可能出现短时响应延迟；百万级合成数据回归不等同于真实全盘扫描的内存和帧时间保证。
- 概述根目录清单汇总阶段可能耗时较长，仍存在延迟响应取消的风险。缓存提交阶段不提供取消。
- 清理建议不是删除授权。请先核实用途和可重建性，并保留必要备份。

## 构建产物保留规则

**仅保留 Release 版本。** 此规则适用于后续开发、验证、构建和部署。

- 日常构建、交付和运行均使用 Release 配置。
- 磁盘上的项目构建目录、Xcode DerivedData 和临时验证目录中，不长期保留 CleanMac 的 Debug 应用及其专属中间产物。
- 如果验证必须使用 Debug，验证结束后先停止对应的应用和 Xcode 调试会话，再清理本次 Debug 产物。
- 清理范围仅限已确认属于 CleanMac Debug 的文件；保留 Release 应用、源码、项目配置、扫描缓存及其他项目的构建产物。
- 清理优先移入废纸篓以便恢复。移入废纸篓不代表已释放磁盘空间；清空废纸篓需单独执行。

Release 应用的标准输出位置：`build/Build/Products/Release/CleanMac.app`。

## 输出 Release 应用

在项目根目录运行：

```sh
xcodebuild -project CleanMac.xcodeproj -scheme CleanMac \
  -configuration Release -derivedDataPath build \
  -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual build
```

该命令使用本地签名生成应用，不自动安装或启动。

## 概述与归属分析

“全面分析”或文件系统目录刷新成功后，会自动生成一份临时概述，并弹出“刷新完成，复制给 Agent 分析”文本框。文本可编辑；点击“复制到剪贴板”后，将当前文本写入 macOS 系统剪贴板，再粘贴到可访问本机文件的 Agent 对话框。

文本包含临时概述目录、刷新范围与时间、真实数据文件路径、`cleanmac-disk-analysis` Skill 的完整路径，以及“仅生成建议，不删除”的请求。Skill 随应用打包并复制到每份概述的 `skills/cleanmac-disk-analysis/SKILL.md`，无需另行全局安装。初始交接文本也保存在概述目录的 `agent-prompt.txt`。

目录刷新只导出刚更新的子树；全面分析导出本次扫描覆盖的全部范围。应用启动时恢复缓存、展开已有目录、查询开发库不会弹出该对话框。取消扫描不会生成新交接；概述生成失败时保留刷新结果并显示可重试的错误，不提供虚假的文件地址。生成临时概述期间显示进度，可取消。

扫描、开发库查询、进程观察、归属索引和目录指纹计算会检查取消状态；点击后显示“正在取消”，并保留已有记录。取消后的迟到进度不会覆盖界面状态。启动时读取缓存、完整快照提交保存及实际移入废纸篓阶段不显示取消按钮，避免把不能中断的操作误标为可取消。

全盘扫描和目录刷新结束后的告警整理、子树替换及可见目录行构建均在后台批量完成，并继续检查取消；主线程只对准备好的结果进行固定次数的整体赋值，不逐目录修改 `@Published` 字典。发布前再次检查取消，取消后不替换旧结果、不保存缓存、不弹出新交接框。发布完成后的缓存提交为不可取消阶段。扫描摘要不再额外持有完整目录树，缓存格式仍为版本 1，兼容原有记录。

取消采用协作式检查，不能强行中断 macOS 正在等待授权的文件访问调用。若刷新停在 0 项，请先检查系统的文件夹访问权限弹窗并作出选择。本地临时签名的 Release 在重新构建后可能需要重新授权；只有用户允许后才能读取相应受保护目录。

在侧边栏打开“概述与归属分析”。先完成一次目录扫描，再选择“临时概述”或“持久化概述”并生成。此操作读取已有扫描缓存，不刷新原扫描记录；同时只读采集当前可见的应用清单、launchd 服务配置和进程打开文件。

- 临时概述位于系统临时目录下的 `CleanMac-Overviews/<UUID>/`，可能由系统清理。
- 持久化概述位于 `~/Library/Application Support/CleanMac/Overviews/<UUID>/`，下次启动可从已有概述列表重新打开，无自动过期。
- 点击“分析此概述”生成归属证据、置信度和“保留 / 未知归属 / 待复核”结果。已有概述也可通过选择目录导入并分析，分析不自动重新采集运行时证据；要观察当前状态，请重新生成概述。
- “打开概述目录”提供 `overview.md`、`manifest.json`、`entries.jsonl` 和 `AGENT_GUIDE.md`。可交给本地 AI Agent 继续分析；完整分析逐行保存，界面只预览最多 200 条重点记录。
- 应用或服务关联不等于可删除；未匹配不等于已卸载；未观察到进程打开不等于无人使用。服务配置引用与当前进程观察分别记录。

辅助清理流程为：**生成概述 → 分析证据 → 人工确认用途与可重建性 → 当前状态复核 → 移入废纸篓 → 验证应用与服务 → 再决定是否清空废纸篓**。

新功能中的“复核移除”仅面向 `~/Library/Caches` 下有应用归属证据的直接子项，排除 Apple 和 CleanMac 自身缓存，不默认选择任何项目。执行前重新观察打开文件与服务配置、验证路径没有符号链接跳转，并比较文件标识及整个目录子树的元数据摘要。若观察不完整、文件有变化、存在服务关联或进程正在使用，则保留并提示。AI 建议文件不自动执行，也不接受其中的 shell 指令。

清理审计独立持久化到 `~/Library/Application Support/CleanMac/CleanupAudits/audit-*.json`，即使概述本身为临时文件也保留记录。审计包含概述 ID、原路径、操作状态及废纸篓目标位置。移入废纸篓不代表已释放磁盘空间；此功能不清空废纸篓。

格式、限制及 Agent 交接方式见 [概述协议](Docs/OverviewProtocol.md)。

## 概述功能验证

```sh
zsh Tests/run-overview-checks.sh
```

使用优化编译的独立验证程序，覆盖归属边界、未知归属、服务引用、进程占用、深层目录变化、符号链接、两种概述的导出与重新打开、流式分析、取消时保留旧结果，以及受保护路径的拒绝。验证过程中仅创建并清理专用测试目录，不移动已有用户文件。验证程序会只读调用本机应用/服务清单和 `lsof`；权限受限情况写入概述。

## 大规模结果发布与取消回归

```sh
CLEANMAC_PUBLICATION_DIRECTORIES=1000000 zsh Tests/run-publication-checks.sh
```

默认规模为 250,000 个叶目录，可通过上述参数提升至百万级。使用 `-O` 编译，调用实际的 `ScannerViewModel` 扫描/刷新/发布/持久化链路，扫描输入替换为内存夹具，缓存写入独立临时路径；不扫描、覆盖或删除用户原有缓存，测试文件保留在输出的专用目录中。

覆盖：带权限告警的大规模结果连续发布两次、订阅者保留字典时通知次数保持固定、主线程心跳、整理开始前/整理中/发布前取消、可见行构建取消，以及十万级子树刷新时移除旧条目但保留无关缓存。取消用例核对旧界面数据、缓存原始字节和交接事件均未改变；另设后台看门狗，避免主线程卡死时测试本身无限等待。此为实际 ViewModel 的自动化回归，不等同于新一轮全盘扫描或 SwiftUI 界面验收。
